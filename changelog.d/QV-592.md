- **Alerts page and the alert check in the server** (QV-592). With `TRAILBEAM_ALERT_CHECK` on (minutes, or `on` for
  every 5), the server now runs the scheduled alert check on a thread of its own, started and stopped with the
  server and reported in `/api/health` under `alert_check`. It checks "Alert me" rules on Stuck's causes, and
  dashboard rules when dashboards are on, and sends each change to the rule's channels: Slack, a signed webhook, or
  email through the mail server set with `TRAILBEAM_SMTP_HOST`. The new **Alerts** page (`/alerts`) lists the rules,
  firing first, with their state at the last check and when that was, and the channels with their last delivery,
  where an admin adds, tests and removes them. Each cause on **Stuck** has **Alert me**. Both are the hosted app's
  views, shared through `@trailbeam/ui`. Not yet: a rule is not held while its cause is ignored in triage.
