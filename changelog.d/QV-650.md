- **Alert tables in SQLite and Postgres** (QV-650, part of QV-592). The server keeps alert rules, alert channels,
  each rule's alert state, and each workspace's last check and lease in the store: SQLite schema 26 and Postgres
  schema 20 add the tables `alert_rules`, `alert_channels`, `alert_state` and `alert_checks`, empty. Nothing uses
  them yet: the scheduled check and the alerts API still keep their data in memory until the server is switched
  over in a later change. The lease is one conditional statement, so of two servers on one Postgres database only
  one checks a workspace at a time. A channel's target and a webhook's signing secret are stored as entered,
  because delivery needs them, and the alerts API never returns them.
