---
section: Changed
---

- **Dashboard measures shared by both products** (QV-591, One UI 13, part 1, `@trailbeam/ui` 0.1.0-dev.26). A new
  entry, `@trailbeam/ui/dashboards`, has a dashboard's definition (variables, sections and widgets, and the
  starters) and the widget measures engine, moved from the hosted app. `dashboardMeasures()` makes the engine over
  a query language and, on the hosted app, its sample figures. It gives the same answers as the server's engine on
  all the cases in `contract/fixtures/measures-parity.json`. `fmt` now lives in one place for the charts and the
  measures. Nothing on a page changes yet.
- **Dashboard views shared by both products** (QV-591, part 2, `@trailbeam/ui` 0.1.0-dev.27). A new client entry,
  `@trailbeam/ui/dashboards/views`, has the hosted dashboards list (`DashboardsPage`) and one dashboard on its snap
  grid (`DashboardView`), with the widget editor, sections and every widget type. Each product gives them its engine,
  events, links and the changes it stores through `DashboardsEnvProvider`. The charts entry adds `Spark`, `Heatmap`
  and `Bars`. Nothing on a page changes yet.
- **Dashboards in self-hosted Trailbeam** (QV-591, part 3, `@trailbeam/ui` 0.1.0-dev.28). While the server runs with
  `TRAILBEAM_DASHBOARDS=1`, the sidebar has Dashboards, and `/dashboards` is the hosted app's dashboards on
  `/api/dashboards`: the list, with what each dashboard's widget rules say now, and one dashboard at
  `/dashboards?id=<id>`. You can make, change, star, lock, copy and delete dashboards there. Queue measures (depth,
  age, headroom) say this server does not read them from AWS. `ServerAlerts.check` is now optional.
