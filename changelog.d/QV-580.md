- **The Event explorer's events, inferred ones included, from the server** (QV-580). `GET /api/timeline-events`
  lists what happened to each message active in a time window, made from its timeline: the recorded sends,
  receives, deletes, visibility changes and failed Lambda outcomes, and what the timeline infers, such as an expired visibility
  timeout, a move to the dead-letter queue, the Lambda trigger's delete and a Lambda invocation with no outcome.
  Each event carries the message's tenant, body size and, for queues the server stores bodies for, its body.
  Before, `GET /api/events` listed recorded steps only. The rules are the hosted app's, and a parity test keeps the
  two the same.
- **The hosted Event explorer, in `@trailbeam/ui/explorer`** (QV-580, `@trailbeam/ui` 0.1.0-dev.22). Its query
  bar, chart, filters, columns, opened row, time picker and CSV and PDF export are now in the shared package, read
  from the events the page hands it. Columns and filters that no event in the range fills are left out, Columns and
  Export sit in the results bar over the list, and there are body size and tenant columns. A recorded
  `ChangeMessageVisibility` is an event too, in both products.
