- **Alert webhooks can go to the server's own network** (QV-764, internal until alerts ship in QV-592). Start the
  server with `TRAILBEAM_ALERT_ALLOW_PRIVATE_WEBHOOKS=1` and a webhook or Slack channel may point at a private or
  local address, over https or plain http: an internal Alertmanager, an on-call bridge, a chat relay, a service on
  the same Compose network (`http://listener:8080/hook`). It is off by default, and the Alerts page says how to turn
  it on. Even when it is on, plain http goes only to private addresses (a name is checked on every address it
  resolves to, before connecting), cloud metadata addresses (169.254.0.0/16, fe80::/10, fd00:ec2::254,
  100.100.100.200, 192.0.0.192, and the same inside NAT64, 6to4 and IPv4-mapped forms) are refused, and redirects
  are still not followed. A value other than 1/0 (on/off, true/false, yes/no) stops the server at start.
