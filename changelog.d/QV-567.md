---
section: Changed
---

- **The server is its own Python distribution, `trailbeam-server`** (QV-567). `trailbeam` on PyPI is now the client
  library only (`trailbeam.boto`, `trailbeam.aws_lambda`, `trailbeam.pika`): no server code, no web screen files,
  no `trailbeam` command, so services that only send spans install less. Trailbeam itself (the server, the built
  web screen and the `trailbeam` command: `start`, `doctor`, `users`, `tokens`, `--version`) is `trailbeam-server`,
  released at the same version. Nothing changes in how you install or run it:
  - `pip install "trailbeam[server]"` (and `[server,postgres]`, `[server,sso]`) pulls in `trailbeam-server` at the
    same version, as `pip install trailbeam-server` does on its own. `pip install -U "trailbeam[server]"` upgrades a
    0.4.0 or 0.3.0 install in place; `pip install -U trailbeam` without the extra removes the server.
  - `import trailbeam.server` and `python -m trailbeam.server` still work: `trailbeam-server` installs into the
    `trailbeam` package, and depends on `trailbeam` at the same version, so pip replaces the old single package
    before it adds the server's files.
  - The container images, the Helm chart, Docker Compose and `npx trailbeam start` are unchanged.
  - In the repository the server's code moved from `python/src/trailbeam/server/` to `server/`; work on both with
    `pip install -e ./server -e './python[test]'`. CI checks that the library's wheel holds no server or UI file,
    and the upgrade test now also starts from 0.4.0, upgrading its pip install in place.
