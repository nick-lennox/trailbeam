- **An S3 write made without Trailbeam is no longer joined to a recorded upload of the same key** (QV-562; contract
  revision 3.7, sections 23.2 and 27.3). Before, if the console, `aws s3 cp` or a Lambda without a Trailbeam package
  wrote the same bucket and key within about two seconds of a recorded `PutObject`, its notification's message showed
  the recorded upload as its sender, and both messages were listed as reached by it. On a queue whose body is
  captured, the Python and Node.js receives now also record the S3 record's `eTag` and `versionId`, and the server
  joins only an upload whose ETag (quotes aside) and VersionId match where both sides have them. The same check tells
  apart different keys that redact to the same text. It can't tell apart a write of the same bytes in a bucket
  without versioning. Postgres schema 19 adds two columns to `s3_receives`, applied on start.
