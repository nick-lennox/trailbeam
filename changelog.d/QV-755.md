section: Changed
---

- **Only a browser sends an invite or reset link either** (QV-755). With an admin's personal API token or a sign-in
  through the proxy, `POST /api/users` still adds the person but emails nothing (`email` is `null`; `"send_email":
  true` is `403`, `reason` `needs_a_session`, and nobody is added), and `POST /api/users/{id}/link` is always `403`
  `needs_a_session`. The token chooses the address when it adds the person, so with a mail server set up it could
  add `eve@attacker.example` as an admin, have the invite emailed there, and add a passkey that keeps signing in
  after the token is revoked. People who sign in through the proxy are added on their first sign-in and need no
  invite; to invite someone with a password, sign in in a browser. The People page no longer says a link was
  emailed when it wasn't.
