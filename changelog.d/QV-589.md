- **AWS reads and the figures from them, shared by both products** (QV-589, part 1). The figures the hosted app works
  out from a queue's AWS reads are now in `@trailbeam/ui/model` (`aws.ts`): its settings from `GetQueueAttributes`,
  the CloudWatch period for a window, the figures now, a queue's figures for the Overview, the dashboards and alerts,
  and the queue page's AWS part. The server has a Python port of them (`trailbeam.server.aws_figures`), and
  `contract/fixtures/aws-figures-parity.json` holds the cases both must agree on. The reads themselves
  (`GetQueueAttributes`, `GetMetricData`, `ListEventSourceMappings`, never `ReceiveMessage`) are in
  `trailbeam.server.aws_reads`, with boto3 from a new optional install, `pip install "trailbeam[server,aws]"`. Nothing
  calls them yet: the server still makes no AWS calls.
