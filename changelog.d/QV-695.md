section: Changed
---

- **A password reset removes passkeys, and only a browser adds one** (QV-695). A reset link, or
  `trailbeam users reset-password`, now removes the person's passkeys along with ending their sessions, so a
  passkey someone else added to the account stops signing in; the reset page says so. Adding a passkey needs a
  browser session: a personal API token or a sign-in through the proxy gets `403` (`reason` `needs_a_session`), and
  `GET /api/me/passkeys` says `can_add`. Admins see how many passkeys each person has (`passkeys` in
  `GET /api/users`), list them with `GET /api/users/{id}/passkeys` and remove them all with
  `DELETE /api/users/{id}/passkeys`. A passkey added is logged at warning level with the client's address.
