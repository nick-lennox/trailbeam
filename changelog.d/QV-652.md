- **Dashboards in the server: tables and a JSON API, off by default** (QV-652, part of QV-591). SQLite schema 27
  and Postgres schema 21 add the tables `dashboards` (name, owner, time range, variables and sections, lock) and
  `dashboard_widgets` (each widget's definition and its place), empty. With `TRAILBEAM_DASHBOARDS=1` the server
  answers `/api/dashboards`: list, make (from a definition or pasted JSON), rename, star, lock, copy and delete
  dashboards, add, change and remove one widget, and `GET /api/dashboards/{id}/measures`, what each widget draws
  over a time range, worked out from the stored spans by the widget measures engine. The records and error texts
  are the hosted app's, so the shared dashboard views can read either. Any member makes and changes dashboards; a
  locked one changes only after whoever locked it, or an admin, unlocks it. Queue depth, age and headroom need
  figures from AWS, which the server does not read, so those measures say they have no data. Without the setting
  every route is a 404. The routes are in `contract/openapi.yaml` under the Dashboards tag.
