- **RabbitMQ in the app's views** (QV-308, part 4 of 6 of RabbitMQ support). In `@trailbeam/ui` 0.1.0-dev.32, the
  views both products share:
  - **The message page** of a RabbitMQ message has a RabbitMQ badge, shows the ID as the application set it (without
    the `~rabbitmq~` mark), and names each step in RabbitMQ's terms: published to an exchange, routed, delivered,
    acked, requeued, refused, channel closed, returned to the publisher (`basic.return`), returned to the queue with
    its cause, and dead-lettered as the `x-death` header reports it, with its reason. The heading, the state ("Done",
    "No ack seen") and the figures ("Deliveries, acked") use the same words.
  - **One row per queue copy**: the page lists each queue's copy of the message with its deliveries and how it ended,
    so a fanout to two queues is one message with two rows, not a duplicate.
  - **The Event explorer** lists a RabbitMQ message's events by their AMQP method (`basic.publish`, `basic.deliver`,
    `basic.ack`, `basic.nack`, `basic.reject`, `basic.return`, a closed channel), with the RabbitMQ badge, "Returned to
    the queue" with its cause, and the `x-death` move. They were listed as `SendMessage` and `ReceiveMessage`, with no
    acks or requeues. The kinds stay SQS's, so the chart and filters count both systems together; the Event filter
    names them for the systems in range ("Ack", or "Delete or ack" for both). A **System** filter and column appear
    once a RabbitMQ event is in range. `/api/timeline-events` adds `system: rabbitmq` to those events.
  - **The Overview** marks a RabbitMQ queue's card with the badge in place of the SQS mark, says Trailbeam reads
    nothing from RabbitMQ instead of naming AWS, shows `x-delivery-limit` and the `x-death` header for its
    dead-letter queue, and leaves out SQS's visibility timeout, retention and queue type.
  - **The Messages list** shows a RabbitMQ message's ID as the application set it, with the badge, and its state as
    "Done" or "No ack seen".
  - **The first-run screen** has an Amazon SQS or RabbitMQ choice next to Python or Node.js: for RabbitMQ it installs
    `trailbeam[pika]` or `amqplib` and publishes one message with a `message_id`.
  - **Empty states** say what a RabbitMQ message's ID is, and that a final ack ends it. Opening `/message?id=<ID>`
    with the ID a RabbitMQ publisher set finds the message.
  - SQS messages' pages and events are unchanged.
