- **Issues view model shared by both products** (QV-583, One UI 5, part 1). `@trailbeam/ui/model` now has the
  Issues pages' model, `issueOf`, `issuesOf` and `issuesOfPage`, and the age choices (`stuckAge`, `withAge`),
  moved from the hosted app. Each issue is one cause group from `GET /api/causes`, with the same ID. Both
  backends' groups and messages for the contract 3.2 spans now give the same issues
  (`ui/test/fixtures/viewmodel-parity.json`). Nothing on a page changes yet.
- **Issues views shared by both products** (QV-583, part 2, `@trailbeam/ui` 0.1.0-dev.25). A new entry,
  `@trailbeam/ui/issues`, has the hosted Issues list (`IssueList`), the body of an issue's page (`IssueDetail`), the
  issue's flow drawing and their parts, the age and queue controls, and `issueRow` for the list's rows. Triage, Alert me,
  redrive and the example message's timeline stay with each product and reach the views through slots. The
  dashboards' time-series chart is in `@trailbeam/ui/charts`, and the design entry has `Menu` and `PlatformIcon`.
  Nothing on a page changes yet.
