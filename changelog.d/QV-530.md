- **RabbitMQ: header values over 255 bytes are no longer copied to spans** (QV-530; contract A3, A8, A12). The
  pika and amqplib hooks copied `x-death` and `x-first-death-*` values from the publisher's headers verbatim, so
  one publisher sending 60,000-character queue names made the store 78 times larger and put the name in the
  queue list. The hooks now drop any string they copy from the broker or the headers (queue, exchange, routing
  key, consumer tag, message ID, reply text, dead-letter values) that is over 255 bytes in UTF-8, the AMQP short
  string limit. The server rejects an `amqp.*` span whose queue, exchange, virtual host, channel ID or consumer
  tag is over 255 bytes, drops any other string attribute over it (except the captured body), and cuts
  `trailbeam.tenant` to 256 characters.
