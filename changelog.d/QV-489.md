- **EventBridge PutEvents is recorded and joined to the SQS messages its rules delivered** (QV-489; contract
  revision 3.6, section 25). The Python hooks (boto3 `events` clients, with `trailbeam.boto.install()`) and the Node.js
  hooks (an `EventBridgeClient` passed to `instrument`) emit one `trailbeam put_event` span per `PutEvents` entry:
  accepted, failed (with its `ErrorCode`), or failed with the whole call. Each span has the bus, the event ID, `Source`,
  `DetailType` and the size of `Detail`, never `Detail` itself. Trailbeam joins an entry to every receive whose
  EventBridge body has the same `id`. The message's timeline then starts with an observed "Put on EventBridge bus"
  step, with the other SQS messages the event reached and the EventBridge delivery time (`SentTimestamp` minus the
  event's `time`), instead of the inferred "Arrived via an EventBridge rule". `GET /api/messages/{id}` has a new
  `put_event` step type. Stores: SQLite schema 23 (two indexes), Postgres schema 17 (table `eventbridge_events`),
  both applied on start.
