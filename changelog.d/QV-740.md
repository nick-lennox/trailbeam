- **AWS reads go only where an admin's settings allow** (QV-740). Before, any signed-in member, or anyone sending
  spans while ingest was open, could make the server read any account's queue with its own AWS credentials: by
  opening `/api/queues/{queue}/now` for a key such as `999999999999/ap-south-1/billing-secrets`, or with a queue
  URL that names no account. Now a queue is read only when the store has spans for it, its name is a valid SQS
  name the settings list, it is in the settings' AWS account (left empty, the credentials' own account, found
  with `sts:GetCallerIdentity`), and it is in the settings' region or one of the new **Other regions**. Its URL
  is always built from those, never taken from spans. Upgrading: a server that reads queues outside its default
  region must now list those regions in Settings, under AWS. A server using an SQS emulator must set the
  emulator's account ID (`000000000000` for ElasticMQ). The README shows a policy that names the queues' ARNs.
