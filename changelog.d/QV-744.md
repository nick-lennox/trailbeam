- **Server health no longer tells non-admins where the AWS credentials come from** (QV-744). With AWS reads on,
  `/api/health`'s `config.aws` gave every signed-in person the credentials' source (`env`, `iam-role`, …), the
  region, the number of queue names and the problem text. Now only an admin (anyone, before accounts exist) gets
  those. Anyone else gets `on`, and whether reads can work. A request that isn't signed in still gets only
  `status` and `version`. `trailbeam doctor` with a member's token says reads are on, or that they can't work and
  that an admin sees why in Settings, under AWS.
